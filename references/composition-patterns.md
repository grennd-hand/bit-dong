# 构图模式与原创规则

## 基础结构类型

选择一种结构即可，不要混太多。

### Workflow 流程

适合：输入 -> 处理 -> 输出，内容生产，AI 工作流，自动化链路。

画法：左侧输入，中间由 Bit东操作怪机器处理，右侧输出，橙色箭头表达主流向。

### 系统局部

适合：信息来源、过滤器、数据库、渲染器、agent 系统局部。

画法：只画 3-5 个核心模块，Bit东参与其中一个关键动作。

### 前后对比

适合：混乱/有序，手动/自动，分散/收拢，焦虑/稳定。

画法：左混乱，右稳定，中间橙色箭头。先定义情绪差，例如焦虑 -> 释然、疲惫 -> 期待、失望 -> 自信；同时改变重心、脊柱、肩胸和步态，不能只换脸与手臂；角色可以更明确，但保持成年感。

### 角色状态

适合：用户痛点、创作者状态、工具太多、信息焦虑、卡住到跑起来。

画法：2-4 个小状态，每个状态一个短标注；先写每格的情绪与重心，再写动作。每格必须改变表情、躯干和站姿，不能只是同一张脸换手臂。

### 概念隐喻

适合：内容工厂、信息仓库、脑内黑盒、工作流机器、自动日报。

画法：一个大的怪物件或机器，少量输入，一个输出。要有记忆点。

### 方法分层

适合：方法论框架、系统层级、能力栈、内容系统分层。

画法：一层层盒子，不要正式金字塔；Bit东在其中搬砖或搭建。

### 地图路线

适合：从想法到上线、用户路径、内容承接路径、学习路线。

画法：一条弯曲路径，少量节点，Bit东牵线或走路。

### 小漫画分镜

适合：失败到成功、真实过程、吐槽、使用前后变化。

画法：2-4 个小场景，每格只表达一个动作。先写情绪弧线和身体弧线，再写动作，例如收缩后退 -> 谨慎前探 -> 扎实站定，让读者看见角色经历了什么。

## 原创隐喻生成法

每次都从当前文章重新发明隐喻，不能照搬旧图。

### 三步

1. 把抽象概念换成一个物理动作：卡住、漏掉、变重、分拣、沉淀、发酵、开门、折叠、拆包、回流。
2. 把系统结构换成一个低科技物件：坏掉的机器、纸箱、抽屉、水管、邮筒、怪表盘、秤、井、梯子、奇怪工位。
3. 让 Bit东承担动作：不是站旁边，而是修机器、接线、守门、搬运、修补、称重、扶梯子、记录、把东西塞进某个怪装置。

### 可用物件池

- 纸箱、抽屉、旧机器、漏斗、秤、邮筒、门、井、梯子、水管、线团、闸门、转盘、黑盒、打孔器、压面机、晾衣绳、怪工位。
- 用时只选 1-2 个，不要堆满。

### Bit东动作池

- 拉、扛、塞、捞、压、称、缝、剪、拧、守、推、接、拆、标记、回收。
- 动作要服务核心意思，不要为了怪而怪。

## 反复刻规则

不要默认打开或复刻 `assets/examples/`。这些是含旧角色的历史案例，只能在明确需要时校准线条密度、留白和颜色克制，绝不能作为人物参考。角色只能参考 `assets/character-reference/`。

除非用户明确说“照这张 / 复刻这个构图 / 用这个案例改”，否则不要直接复用这些旧构图：

- 传送带两个断点
- 角色在内容机器里拉判断杆
- 角色或身体变成漏斗分拣流量/信任/转化
- 角色切素材鱼
- 角色牵承接路径
- 角色拉三层信息源
- 三个角色分别拿喇叭/搭桥/开门
- 角色盖章话术工具箱
- 角色举牌看常见坑路径

同类主题也要换新隐喻。例如“承接路径”不一定画路线，可以画 Bit东把内容尾巴接到门把手；“一鱼多吃”不一定画鱼，可以画 Bit东把一个纸团压成几种形状。
