# Bit东角色与视频质检

## 状态与证据

每项结果只使用 `not_run`、`pass`、`fail`：

- `not_run`：未取得对应图/视频、未检查该项目，或只有提示词/计划。
- `pass`：已检查实际文件，记录文件、版本、检查范围与必要的时间点。
- `fail`：已观察到具体偏差，记录问题位置和需要重做的部分。

不适用项目写明原因并保持 `not_run`，不要靠默认全选获得“全部通过”。
脚本能检查路径、尺寸、哈希与字段；脚本通过不等于角色视觉一致，也不等于真实视频测试通过。
当前候选集的图像检查不能证明任何视频模型已实测。没有实际视频输出时，所有视频运动项目保持 `not_run`。
外观检查 `pass` 不自动把 `candidate` 改成 `approved`；批准记录与测试结果分别保存。

## 1. 生成前

- 写明 `design_version`、所选母版/候选 `set_id` 与具体参考文件；不得混用不同版本。
- 当前基线为 `1.0-inherited`，新套装为 `bitdong-v2-candidate-20261030`；`approved_master_set` 仍为空。
- 排除旧鞋版和 archived 案例；不把表情拼图当成视频首帧。
- 明确平台、入口、实际模型、输入模式与素材职责；核验后才能写支持的参数。
- 只提供提示词或分镜时，交付状态明确为计划；不能声称已生成、已上传或已测试。

## 2. 单张角色图与镜头首帧

- 单角色、完整目标部位；母版无拼格、标签、额外人物，发顶与鞋底不意外裁切。
- 同角度比对脸型、发际线、眼镜框形/镜腿、成人眼睛与整体轮廓；不以“粉色上衣相同”代替身份检查。
- 角色保持成年感、相同身体比例、2D墨线与克制赛璐璐；未变成写真、3D或不同年龄。
- 粉色圆领无帽卫衣、银链、炭黑裤保持相同设计；没有自动加入原照片胸口纹章。
- 候选左腕手表保持同侧；遮挡不可见可以接受，换腕、复制或无理由消失需记录失败。
- 可见鞋子保持黑色高帮、米白中底、蓝红主要区域；近景进一步核对字样与不对称图案。
- `shoe_A_BIT` / `shoe_B_DONG` 的左右脚映射仍未核实；不把猜测当成通过依据，不水平镜像冒充另一侧。
- 真侧面只有符合侧视的面部结构，背面没有多余眼睛/正脸；新增未见结构记录为推断。
- 手部指节、指向和接触点可信；眼镜不能穿过眼睛、耳朵或手掌。
- 按原文件记录真实尺寸；插值放大或从拼图裁切不算新增原生细节。若交付要求超过实际尺寸，则尺寸项为 `fail`。
- 场景首帧另检查构图、道具、目光、镜头方向和画幅，保证与镜头任务相符。

当前四张全身候选图为1024×1536，另有一张1254×1254的正面面部近景。鞋帮小字、图案和后跟细节存在已知差异，见 [角色规范](bitdong-character.md)；不得将整套写为“所有细节已通过”。

## 3. 视频运动与跨镜头连续性

先观看完整片段，再检查首帧、中间帧、末帧以及下列实际发生的事件；不要仅凭一张封面判定视频合格。

| 检查点 | 观察对象 |
| --- | --- |
| 首/中/尾 | 同一角色脸型、眼镜、衣服、鞋型、身体比例与色彩是否稳定 |
| 转头/转身 | 眼镜腿、鼻口轮廓、发型、后脑和左右关系是否连续，无换脸或多眼 |
| 眨眼/口播 | 眼睑闭合正确，瞳孔无残留；嘴型不带动镜框变形或牙齿闪现 |
| 遮挡与恢复 | 手/物体挡住脸后仍恢复同一脸；银链、眼镜、衣袖与道具没有换样 |
| 手触脸/扶眼镜 | 接触位置、手指数量和遮挡层次可信，不融化或穿模 |
| 行走与落脚 | 支撑脚落地、重心转移和脚步方向正确；不滑步、穿地或中途换鞋 |
| 道具交互 | 握持手、物体数量与位置连续，接触和释放过程成立 |
| 镜头衔接 | 前镜结束状态与后镜开始状态相容，视线、位置、手位、朝向与道具承接 |

- 背景、光线和镜头运动依本镜头任务验收；不把视频强制成白底16:9。
- 中性或持续专注可以通过；只有情绪与剧情冲突、机械抖动或无因切换才需要返工。
- 鞋上小字在远景不可读不自动失败；鞋型/主要配色改变，或近景字样持续错误需要修正。
- 固定 seed、重复同段提示词或平台任务成功返回，都不能代替实际连续性检查。

## 4. 文章插画专用规则

仅当明确使用原文章插画模式时执行：

- 16:9横版、干净白底、成熟动漫人物与简洁手绘场景、大量留白。
- Bit东承担正文的核心动作；一图一个认知节点或隐喻，避免变成密集课件。
- 中文标注少、短、可读；无多余类型标题，不照抄 archived 案例。
- 情绪与正文节点相符，身体参与表达；连续叙事允许保持相同情绪。

这组规则不适用于视频场景、通用角色转面、用户明确指定的海报或其他画幅。

## 5. 修正与记录

先修身份、结构和连续性，再修细节与美观。只修改出现问题的图或镜头，保留原输出与最终提示词。
回到同一选定母版/候选图修正；不要为修表情重新混入自拍、旧鞋图或另一角色版本。
重做后的文件重新检查，旧 `pass` 不能自动沿用。

最小记录字段：

```text
artifact: 实际文件或任务输出
design_version / set_id: 本次角色版本
provider_surface / model: 实测入口和型号；未运行则留空
check: 检查项目
result: not_run | pass | fail
scope: 检查的视图、镜头与时间点
evidence_or_reason: 实际观察或未运行原因
fix: 仅在需要时记录下一步修正
```

交付时分别说明素材状态、图像检查、真实视频测试结果与尚未解决项；不把“准备好输入包”写成“跨平台生成已验证”。
