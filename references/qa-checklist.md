# QA Checklist

## 必过项

- 是 16:9 横版。
- 背景是干净白底。
- 有 Bit东个人角色。
- Bit东承担核心动作，不只是装饰。
- 短刺黑发、深色矩形眼镜、粉色卫衣、银色链条、定制黑色高帮鞋五个锚点一致。
- 全身或脚部可见时，鞋子保持黑色高帮轮廓、米白中底、蓝色侧边图案和红粉色鞋头图案；近景还要有不对称的“BIT / DONG”、紫色小图案与黄橙色后跟线稿。
- 角色脸型、年龄和成人比例与参考图一致，没有漂成另一个人。
- 角色是成熟现代动漫风：利落墨线、自然成人眼睛、约 7-7.5 头身、克制赛璐璐明暗。
- 表情与当前叙事节点一致；遮住文字后，仍能从眉眼嘴、头部、肩颈和手势读出感受。
- 中景或全身图里，遮住脸后仍能从重心、脊柱、肩胸、步态、手势和空间距离大致读出状态。
- 脸与身体表达同一方向；多格或多图不会只换手臂而重复同一站姿。
- 情绪使用 1-2 级为主，清楚但保持成年感；不是永久扑克脸，也不是夸张颜艺。
- 多图或分镜中有情绪变化，相邻画面不会只换动作却共用同一张脸。
- 动漫人物与简洁手绘场景自然融合，人物精致但画面仍有大量留白。
- 没有旧版小黑、黑色实心小怪物或无关吉祥物。
- 没有复刻旧案例构图，而是为当前文章生成了新隐喻。
- 画面怪诞、有创意、有意思。
- 简洁清爽，主体不超过画面约 60%。
- 一张图只讲一个核心结构。
- 中文标注少、短、能读。
- 橙色只用于主路径或箭头。
- 红色只用于重点、问题、提醒或结果。
- 蓝色只用于补充说明、反馈或系统状态。

## 失败信号

出现以下情况，重生成或局部编辑：

- 左上角有“常见坑 / Workflow / 系统架构图 / 路线图”等标题。
- Bit东像吉祥物、表情包、Q 版或可爱卡通。
- Bit东表情空白、与正文冲突，或连续多张只有冷静中性脸。
- 只改变嘴角，眉眼、视线、头部和身体仍然没有反应。
- 身体像直立木偶，只改变手臂；重心、脊柱、肩胸和腿部没有随叙事变化。
- 脸与身体冲突，例如脸在同理倾听，身体却后仰、收胸或准备离开。
- Bit东像未成年、萌系、大眼角色、校服角色或通用动漫帅哥。
- 人物退回旧式照片描边草图、粗糙抖线，或变成 3D、写实摄影。
- 眼镜、发型、粉色卫衣或银色链条丢失，人物辨识度不足。
- 鞋子被画成普通运动鞋、低帮鞋、纯黑鞋或白鞋，或丢失米白中底和蓝红定制图案。
- 出现旧版小黑、黑色实心小怪物、白点眼生物或额外角色。
- 画面像 PPT、课程课件、正式流程图。
- 元素太多、箭头太多、节点太多。
- 文字变成大段解释。
- 背景有纸纹、阴影、渐变、米色、噪点。
- 真实 UI 截图或科技感界面。
- 中文错字严重或标注不可读。
- 画面太死板，没有荒诞隐喻。
- 和 `assets/examples/` 里的旧案例构图过于相似。

## 迭代方法

- 太普通：让 Bit东成为动作主体，加入一个奇怪但成立的隐喻。
- 太复杂：删节点，只保留一个动作和 3-5 个短标注。
- 太可爱：保持 mature adult anime、7-7.5 heads tall、natural-sized eyes、controlled adult emotion、not cute、not mascot；不要用中性脸掩盖问题。
- 太没感情：从 `emotion-system.md` 选择情绪与 1-2 级强度，写出触发原因，并同时指定眉眼嘴、头部、肩颈和手势。
- 身体语言太弱：加载身体语言表，至少指定重心、脊柱、肩胸、站距或步态、手势、空间距离中的四项；优先修正躯干和双腿，再修手臂。
- 多张脸重复：先为整组图片写情绪弧线，再逐张生成；连续三张不得都用中性或专注。
- 太像通用动漫脸：重新加载照片和角色卡，锁定偏长脸型、刺发轮廓、粗框矩形眼镜与冷静眉眼。
- 鞋子太普通：重新加载鞋子参考板，锁定黑色高帮轮廓、米白中底、蓝色侧边弧形图案、红粉色鞋头图案和“BIT / DONG”外侧鞋帮字样。
- 太 PPT：去掉标题、边框、整齐网格和过多箭头，改成手绘场景。
- 太像旧案例：保留核心意思，换掉主物件和 Bit东的动作。
- 文字错：优先局部编辑；错得多就重生成并减少标注数量。

## 交付判断

高质量图应该让读者先觉得“有点怪”，然后 1 秒内看懂结构。

如果第一眼像教程页，而不是白纸上的怪诞产品草图，就不合格。
