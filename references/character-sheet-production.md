# 角色母版制作与定稿

## 目标与顺序

先制作可靠的单角色正面，再由它派生其他视角。每张独立交付，避免多视图拼板里各人物的脸、鞋和比例互相漂移。

| 资产 | 构图 | 作用 |
| --- | --- | --- |
| 正面全身 | 正对镜头，中性站姿，头脚完整，双手可见 | 身份、身形与服装基准 |
| 三分之四全身 | 身体与脸朝同一方向，双手放松 | 对话与广告常用角度 |
| 90°侧面全身 | 真正侧面，明确鼻尖朝屏幕哪边 | 转头、行走、侧面轮廓 |
| 背面全身 | 背对镜头，保留后脑、领口、裤型与鞋跟 | 转身与背拍；未知结构标为推断 |
| 正面面部近景 | 完整发际线、耳朵、眼镜、下颌 | 修眼、锁脸与表演参考 |
| 按需补充 | 三分之四面部、另一侧、鞋细节、口型、手势 | 为实际镜头补缺 |

正面口播可先完成正面首帧与草案，不必等待全部视角。需要360°旋转时，不能把缺失另一侧视图当作已覆盖。

## 生成与检查

1. 查看当前动漫设计与定制鞋来源，列出要保留的身份项。原真人照片仅用于身份修订，不覆盖动画服装和渲染。
2. 生成正面：单人、中性背景、均匀光线、闭口中性表情、完整头脚与自然手部。母版白底不限制成片背景。
3. 检查脸型、镜框、成人比例、上衣无帽、服装颜色、双手和鞋轮廓。失败则先修正面。
4. 以同一正面为父参考派生其他视角；只改角度，不同时改情绪、衣服、画风和光线。区分屏幕左右与角色自身左右。
5. 原资料没有充分规定的后脑、背部、镜腿和鞋跟结构，记录为推断；不要说成用户早已确认。
6. 保留真实生成提示与父参考ID；以版本目录保存，记录实际宽高、SHA256和问题。

## 参考职责示例

```text
图1：当前Bit东动画正面母版，负责身份、脸型、眼镜、比例、服装和画风。
图2（确有需要时）：定制鞋原始细节，只管鞋型、配色和图案；
不继承照片背景、光线或写实质感。
本次只将角色旋转到指定视角，保持同一人物与服装。
```

不同时塞入真人自拍、两张情绪拼板、姿态拼板、旧鞋版和广告背景。参考数量与模式按实际平台确定，图多不等于一致性更好。

## 分辨率与格式

- 独立全身长边1536像素及以上是制作目标，近景保留足够眼部细节；这不是视频平台硬性参数。
- 记录真正输出的宽高。请求高分辨率但得到1024×1536时，如实标记，不称为2K/4K。
- 不插值冒充细节增强，不把低清格子裁切后改名“高清母版”；需要细节时重新生成/编辑并验收。
- 保留原始PNG或无额外有损重编码的文件。透明版使用支持透明的图像工具并记录alpha；实际视频首帧应有明确背景。
- 一张图只放一个角色，不印标题、标签、色卡、网格或水印；标签放在登记表。

## 验收与冻结

完成整套可比较的候选与差异说明，再让用户选定有实质差异的外观。普通沿用当前版本的镜头不再重复确认角色。

用户明确选定后：

1. 核实每张文件及哈希，未选图片保留候选或归档。
2. 为选定套装记录一致的 `set_id`，不要混用互相冲突的图。
3. 选中素材改为 `approved`，填写真实 `provenance.approved_by`、`approved_at` 与决定依据。
4. 更新 `character-canon.json` 的 `approved_master_set`，有外形变化时更新 `design_version` 和镜头计划。
5. 运行打包校验。图像验收与脚本校验分开，脚本无法判断脸型与镜框是否好看。

## 当前候选范围

`video-v2-candidates/` 提供正面、三分之四、朝屏幕右侧的侧面、背面和正面面部近景，均来自同一新正面。它们是独立候选视角，不是完整360°模型、绑定模型、训练权重或视频实拍结果。

本次全身图真实为1024×1536；其他图尺寸以登记表为准。鞋子精细字样、侧纹与后跟图案仍存在差异，不能宣称精确复刻。新背面和左腕手表为待选定设计；BIT/DONG左右脚、口型范围与另一侧视图按实际镜头补齐。

## 跨侧鞋款精修与中断恢复

BIT 对应红色D形标记及圆头图案；DONG 对应红色Z形标记及带身体人物图案。左右脚对应尚未由原鞋照确认，不能以镜像图补全；详见 [鞋款识别与对侧图验收](shoe-identity.md)。DONG外侧蓝色轮廓的内部纹样、鞋头小字与后跟细线必须分别检查。

2026-10-30 中断工作报告本地新增8张图，但远端仍只有30张登记图片、5张视频候选图。没有取得那8张原始文件、生成提示和SHA256前，不增加登记项、不宣称已通过新母版视觉验收。后续恢复流程见 [中断恢复记录](recovery-2026-10-31.md)。
